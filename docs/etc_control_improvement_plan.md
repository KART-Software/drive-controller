# ETC 制御改善計画 — モデルベース化とバネ補償フィードフォワード

作成: 2026-08 (PID レビューと制御方式検討の議論のまとめ)

## 1. 背景 / 現状の症状

- **目標開度まで行ききらないことが多い** (定常偏差・整定の遅れ)
- **オーバーシュートが大きい**

現行実装: `etc::MotorController` が 1 ms ISR で `PID(target, TPS)` → duty を
`DcMotor` (G2 18v17, ±100% 飽和) に出力。ゲインは `k_p=3.0, k_i=0.4, k_d=0`
(`default_config.hpp`)。

## 2. 原因分析 (PID レビュー結果)

2 つの症状は別問題ではなく「保持 duty を I 項が一手に担っていて、その I が遅い」
という同じ構造の表と裏。

1. **行ききらない**: リターンスプリングは開度が上がるほど強い。目標付近では
   誤差が小さく P 項 (3×誤差) では押し切れず、力の釣り合いで停止。そこから
   I 項が保持 duty を積むが、速度は 0.4×誤差 %duty/s しかない。加えて
   スティクション (静止摩擦) が動き出しをさらに遅らせる。
2. **オーバーシュート**: 届かない時間中も I は積分し続け、スティクションが
   切れた瞬間に過剰な I が目標を突き抜ける。巻き戻しも同じく秒オーダー。
   閉じ方向も同様 (高開度の保持 duty を抱えたまま下げる)。
3. **anti-windup が未配線**: `PID::setIntegralLimit()` は実装済みだが
   呼び出し元がゼロ (`integralLimit = -1` のまま = 無効)。出力が ±100% に
   飽和しても errorSum が無制限に成長する。

その他のレビュー指摘 (優先度低):

- `setPidGains` (loop) と `compute` (ISR, 優先度 0) の競合 — `noInterrupts()`
  保護が規約上望ましい。
- kI 変更時に積分寄与がジャンプする (`errorSum` が生誤差積分のため)。
- D 項は derivative-on-error (現状 kD=0 なので実害なし)。

## 3. 方針: PID + バネ補償フィードフォワード

検討した選択肢と結論:

| 選択肢 | 結論 |
|---|---|
| PID + FF (バネ補償) | **採用**。両症状の根治。実車 ETC の業界標準構成 |
| LQR / LQI | 見送り。素の LQR は積分なし=定常偏差が悪化。LQI+FF でも PID+FF と同等性能。同定データは共通なので後から移行可能 |
| NN フィッティング | 制御ループには載せない。オフラインで灰箱モデルの妥当性テスター (予測誤差比較) として使うのは可 |
| オンライン学習 | 不採用。ベースはオフライン同定。ドリフト吸収は I 項が担う (ECU のベースマップ+フューエルトリムと同じ役割分担) |

## 4. プラントモデル (同定・シミュレーション用)

入力 = duty 指令 u (−100〜+100%)、出力 = TPS 開度 θ (0〜100%)。

### 記号定義 (本書全体で共通)

| 記号 | 意味 |
|---|---|
| `θ` [%] | スロットル開度 (TPS 換算値)。`θ̇`, `θ̈` はその時間 1 階 / 2 階微分 |
| `θ*` [%] | 目標開度 |
| `u` [%] | duty 指令 (−100〜+100、符号 = 駆動方向)。文中の「duty」は u のこと |
| `i` [A] | モーター電流 |
| `Vbat` [V] | 電源 (バッテリー) 電圧。`Vbat0` = 公称値 (FF マップ測定時の値) |
| `R` [Ω] | モーター巻線抵抗。`R0` = 基準温度 `T0` での公称値、`R_est` = オンライン推定値 |
| `T`, `T0` [°C] | 巻線温度 / 基準温度 |
| `α` [1/°C] | 銅の抵抗温度係数 (≈ 0.0039) |
| `L` [H] | 巻線インダクタンス (小さいのでモデルでは無視) |
| `Kt` [N·m/A] | モータートルク定数 |
| `Ke` [V·s/rad] | 逆起電力定数 |
| `J` | バルブ+ギア換算の慣性モーメント |
| `b` | 機械系の粘性摩擦係数 |
| `B` | 総粘性 `b + Kt·Ke/R` (逆起電力由来の電気的粘性込み) |
| `Ku` | duty→トルク利得 `Kt·Vbat/R` (Vbat に比例する点に注意) |
| `Ts(θ)` [N·m] | リターンスプリングのトルク (プリロード込み、θ とともに増加) |
| `Tc` [N·m] | クーロン摩擦トルクの大きさ (= 摩擦帯の半幅) |
| `FF(θ*)` [%] | 開度 → 保持 duty のフィードフォワードマップ |

```
機械系:  J·θ̈ = Kt·i − b·θ̇ − Ts(θ) − Tc·sgn(θ̇)
電気系:  i = (u·Vbat − Ke·θ̇) / R        ← 代数式 (L/R はサブ ms なので状態にしない)
抵抗:    R = R0·(1 + α·(T − T0))
```

- `Ts(θ)`: プリロードにより `Ts(0) ≠ 0`。関数形は区分線形 or 低次多項式。
  リンプホーム段差がある場合は区分線形+切替点。
- `Tc·sgn(θ̇)`: クーロン摩擦 (スティクション)。
- 「負荷で電流が増えてトルクが増す」現象は `−(Kt·Ke/R)·θ̇` (逆起電力項) として
  自動的に含まれる。別項は不要。
- **電流 i を測定できる**ため機械系と電気系を分離同定できる (Kt と R が分離可能)。
- 注意: TPS は `MovingAverage<60>` @**16 kHz** (`SENSOR_SAMPLING_RATE_US 62.5`)
  ≒ 3.75 ms 窓 (群遅延 ~1.9 ms) を通る。同定はこのフィルタ込みの値
  (=制御器が見る値) で行う。(CLAUDE.md の 8 kHz 記述は旧値)
- 注意: `Ku = Kt·Vbat/R` は Vbat に比例する。同定時は電圧を記録する。
- **エンジン稼働中の負圧 (空力) トルクはモデルに入れない**。本車両のスロットル
  はダブルバレル形状で、負圧によるトルクは**常に開き方向**に働く ((θ, RPM)
  依存、負圧の強い低開度・エンブレ時に最大)。ベンチ (エンジン停止) では再現
  できないため同定対象にせず、FF 誤差と同様に PID 残差 (主に I 項) に吸収
  させる。向きが常に一定なので、実走では FF が系統的に過大側になり I 項が
  負側にトリムする形で現れる (= 検証しやすい)。大きさは FF 導入後の実走ログ
  で `Kt·i − Ts(θ)` (定常保持中) として検証し、摩擦帯 Tc に対して無視でき
  なければ第 2 の FF 項 `FF_aero(θ, RPM)` を後付けする (§7-8)。
  **安全上の含意**: 開き方向の外乱はリターンスプリングの閉じ動作に正面から
  逆らう。「エンジン稼働中 (最大負圧) でもバネが摩擦+負圧トルクに勝って
  全閉まで戻れること」はフェイルセーフの成立条件なので、エンジン稼働状態
  でのスプリング復帰を必ず実機確認する (リターンスプリングに関する
  レギュレーション要件とも照合)。なお 2 気筒の吸気脈動・エンジン振動は
  天然のディザとして静止摩擦を崩す方向に働くため、エンジン停止ベンチで
  測る摩擦帯は保守側 (最悪ケース) になる。

### パラメータの出所と更新頻度

| パラメータ | 取得方法 | 更新頻度 |
|---|---|---|
| `Ts(θ)` | 静的ランプ実験のヒステリシス中心線 | オフライン。起動スイープで毎回検証 |
| `Tc` | ヒステリシス半幅 | **毎起動スイープで再測定** |
| `R` | 静止保持中の `u·Vbat/i` (θ̇=0 で逆起電力が消える) | 走行中連続推定 (温度の代理) |
| `Vbat` | ADC 直測 (チャネル要確認) | リアルタイム |
| `J, b, Kt, Ke` | 動的ステップ/PRBS 実験 | オフライン 1 回。LQI に進む場合のみ必須 |

## 5. ランタイム制御則 (ファームに載る形)

モデルを静止保持条件 (θ̇ = θ̈ = 0) で u について逆に解いた形
(記号は §4 の定義表を参照。`dither(t)` = 小振幅高周波の重畳信号):

```
u    = FF(θ*) · (R_est/R0) · (Vbat0/Vbat)  +  PID(θ*, θ)  +  dither(t)
        └─┬──┘   └───┬────┘   └────┬────┘      └───┬───┘      └──┬──┘
     バネ逆モデル   温度補正      電圧補正        残差専任       スティクション
     (保持dutyマップ) (R推定)      (実測)      (小I+anti-windup)  線形化
```

- **FF(θ\*)**: 公称条件 (R0, Vbat0) で実測した「開度→保持 duty」テーブル。
  測定値を直接持つので Kt, J の値を知らなくても運用できる。
- **PID**: FF 誤差の残差だけを担当。I 項は事実上「FF 誤差のオンライン推定器」
  として小さく働く。integral limit 必須。
- **dither**: 小振幅高周波を duty に常時重畳しスティクションを動摩擦化。
  振幅は毎起動測定する Tc 相当 duty の少し上に自動設定 → 摩擦増加に自動追従。

### 経時変化への対応

| 変動要因 | 対処 |
|---|---|
| バッテリー電圧 | 実測して `Vbat0/Vbat` 補正 (学習不要) |
| 巻線温度 (R) | 静止保持中に R を推定し `R_est/R0` 補正。温度換算は不要 |
| 摩擦の変化 (最大の懸念) | **起動時ヘルスチェック (閉ループ 2 点) で毎回再測定** + dither で頑健化 + I 項がセッション内ドリフト吸収 + 摩擦帯幅をログしてトレンド監視 (整備指標) |
| バネ劣化 | シーズン毎 / 整備後に静的実験を再実施 |

起動時ヘルスチェックは市販車 ETC のキー ON 時学習と同趣旨。閉ループで
20% → 40% → 20% と動かし各点の整定 duty と電流を読む (数秒、ストッパー
非接触)。上り/下りの保持 duty 差 = 摩擦帯幅。安全条件: **エンジン停止中
(RPM=0) のみ実行**。

## 6. 同定実験計画

前提となるファーム改修 (§7-2) の後、ベンチで実施。

**重要な前提 2 つ (実機観察より)**:

- **摩擦帯支配**: 実機は低 duty でも 0%↔100% を一瞬で飛び切る。つまり
  クーロン摩擦 Tc がバネトルク Ts(θ) の可動域全体での増分より大きく、
  開ループでは中間位置に静的釣り合い点が実質存在しない。
  → 開ループ duty ランプは不成立。
  また FF 単独の改善幅は摩擦帯に食われるため **FF + dither はセット**。
- **ストッパー非接触ポリシー**: モーター駆動での端への衝突・押し付け保持は
  モーター/メカ寿命を縮めるためやらない。例外は TPS 端点校正 (低 duty・
  数秒・整備時のみ) だけ。バネ駆動での閉側復帰は ETC シャットダウンの度に
  起きる通常動作なので許容。
- **拡張ストッパー構成**: 物理ストッパーを約 −15% / 115% に設定できるため、
  0〜100% の測定は全域ストッパー非接触で行える。ソフト側は TPS が
  **−10% / 110% を超えたら即出力カット** (ガードはコースト、バネ復帰に任せる)。
  既存コードとの整合: `TPS_MARGIN=15` なのでプラウシビリティの回路チェックは
  −15〜115 を正常扱い = ガードが常に先に効き誤ラッチしない。手動ターゲットの
  `MANUAL_MIN/MAX=−10/110` ともガード帯が一致。
  注意: (a) TPS の 0/100 校正はストッパー移設前に行うか、移設後に新端点 raw
  から線形補間で 0/100 相当 raw を算出して設定する。(b) ダブルバレル機構が
  −15%〜115% の拡張ストロークで干渉・シール損傷なく動けることを実機確認。

実験メニュー:

1. **静的マップ (→ Ts, Tc, FF マップ): 閉ループ・ポイント滞在方式**。
   既存 PID で目標開度 0〜100% の 10〜20 点 (拡張ストッパー構成なら全域可)
   に順に保持し、各点で整定後の平均 duty と電流を記録。**上り順と下り順の両方**を取り、差分から摩擦帯
   (ヒステリシス、幅 = 2·Tc 相当) を得る。閉ループデータのバイアス問題は
   動特性フィットの話であり、平衡点の読み取り (θ̇=0 で u = 保持 duty) には
   影響しない。
   今の未改善 PID でも整定待ちを長めに取れば実験には使える。
2. **機械系ダイナミクス (→ Ts/J, b/J, Tc/J): リリース試験**。
   閉ループで 40〜80% に保持 → 出力カット (SLP=LOW でコースト) → バネ駆動の
   閉じ戻り軌道を 1 kHz 記録。コースト中は電流 ≈ 0 でモーター項が消え、
   純粋な機械系データになる。開始位置を変えて数回。
   **注意**: カット後は TPS が target から離れていくため、実験モード中は
   target-vs-TPS プラウシビリティチェックを `setCheckFlags` で一時無効化する
   (でないと 1 s で復帰不可ラッチ)。回路チェックは有効のままで良い。
3. **モーター系 (→ Ku): 閉ループ中間ステップ応答** (例: 30%→60%)。
   実印加 u をログし、入出力の組 (u, θ) にシミュレーション誤差最小化で
   フィット (加振は目標値側から入れる)。**2 次が本当に要るか検証する** —
   J が小さく実質 1 次 (`θ̇ = (Ku·u − Ts(θ))/B`) なら、以後オブザーバ不要に
   なり大幅に楽。
   **閉ループ同定可能性の注記**: LTI 制御 + 外部加振なしでは閉ループ同定は
   不能 (u = −C·y の縛りでプラントと制御器を分離できない) だが、本実験は
   目標値 r からの外部加振 + u 実測 + C 既知 (ファームの kP/kI/kD) で救済
   される。①は平衡点の読み取りのみで伝達関数を当てない、②は u=0 の開
   ループ応答なので、この問題の当事者は③だけ。
   **検証 (2 コントローラ法)**: ③を 2 種類のゲインセット (例: kP=3 と kP=6,
   `SetEtcPidCmd` で切替) で取り、フィットしたプラントが一致することを
   確認する。閉ループバイアスや未モデル動特性が残っていればコントローラ
   依存のずれとして現れる = 一致がフィットの信頼性の証拠になる。
4. フィットは PC (Python/scipy) でオフライン。θ̈ を数値二階微分で作らず、
   モデルを積分して軌道を再現するシミュレーション誤差最小化でフィットする。
   通常走行の閉ループログは同定に使わない。
5. (任意) 小さい NN を同データでフィットし灰箱と予測誤差を比較 → 大差が
   つけば物理モデルの取りこぼし (温度・ガタ等) のシグナル。

実験モード共通ガード (ファーム側に実装):

- TPS が **−10% / 110%** を超えたら即出力カット (拡張ストッパー −15/115 の内側。
  標準ストッパー構成で実験する場合は 5〜95% 帯域に縮める)
- 「θ̇≈0 かつ duty>閾値」がストール時間上限を超えたら出力カット (押し付け防止)
- リリース試験中は target-vs-TPS チェックを一時無効化 (終了時に復元)
- エンジン停止中 (RPM=0) のみ実行可

## 7. 実装ロードマップ

1. **即時 (1 行)**: `MotorController::initialize()` で
   `pid.setIntegralLimit(DC_MOTOR_OUTPUT_SCALE_MAX)` — anti-windup 有効化。
   あわせて `setPidGains` の `noInterrupts()` 保護。
2. **計測基盤**: PID 出力 (duty) をテレメトリ / SD ログに追加 (現状どちらにも
   無い)。モーター電流 (G2 の CS, ~20 mV/A) と Vbat の取得経路を確認しログに
   追加。
3. **実験モード**: 閉ループ・ポイント滞在シーケンス / リリース試験 /
   中間ステップ印加のテストモードを追加 (§6 の共通ガード込み・console から
   起動)。ポイント滞在のコードは後の起動時ヘルスチェックにそのまま再利用する。
4. **同定**: §6 の実験 → PC フィット → FF 係数決定。
5. **FF 導入**: `cycle()` に FF 項追加。係数は `Config` に載せ console から
   `SetConfigCmd` で流し込み (ファーム再ビルド不要で反映できる)。
   proto 拡張 → 両側再生成 → `overlayConfig()` に 1 行追加を忘れない。
6. **補正項**: dither (FF とセット) → Vbat 補正 → R 推定補正 →
   起動時ヘルスチェック、の順に追加。各段階でゲイン再チューニング
   (FF 後は kP きつめ / kI 小さめに振り直せる)。
7. **(ステージ 2, 必要になったら)** 速度制御へ移行 —
   **P/PI カスケード (速度を制御量にする)** または LQI (実質等価)。
   - 構造的利点: バネ保持 duty を速度ループの積分器が高速に保持・追従する
     ため FF マップへの依存が減る / スティクションを速度誤差の積分が
     即座に押し切る / 速度指令の飽和 = 接近速度制限でオーバーシュートを
     運動学的に抑止。
   - **速度推定 (決定 2026-08-13)**: 16 kHz サンプルの **1 ms ブロック平均の
     隣接差分** `v_k = (mean₁₆(k) − mean₁₆(k−1)) / 1ms`。ノイズ 1/4 (16 平均)、
     群遅延 ~1 ms、同一センサー差分なので**バイアスフリー** (位置ドリフト
     しない)。改良候補: 32 サンプル最小二乗傾き / 逆起電力推定
     `(u·Vbat − R·i)/Ke` との相補フィルタ (要 R, Ke = 同定後)。
   - 実装時の注意: ブロック和の蓄積 = サンプリング ISR、読み出し = モーター
     ISR。ダブルバッファ + 割り込み保護で受け渡す。位置 (MA60, ~1.9 ms) と
     速度 (~1 ms) の群遅延差に留意。
   - **ループレート**: 外側 (位置 P + θ̇* 飽和) も内側 (速度 PI) も同じ
     1 kHz motor ISR 内で直列に回す。カスケードの分離は帯域 (ゲイン設計:
     内側 ~50–100 Hz、外側はその 1/3〜1/5) で確保するもので、演算レートを
     間引く理由はない (間引くと θ̇* が階段状になり内側への段差外乱になる
     だけ)。ISR の構造・周期は現行から不変。
   - **速度指令則 (外側ループ)**: トラッキングサーボなので軌道生成器は使わず
     `v_cmd = clip(Kp_pos·(θ*−θ) + dθ*/dt, ±v_max)`、|e| < e_db (~0.3%) で 0。
     P 項 = 比例接近 (運動学的オーバーシュートなし, Kp_pos [1/s] ≒ 外側帯域)、
     飽和 = 接近速度制限、dθ*/dt = ペダル追従の定常遅れ解消 (要軽フィルタ)、
     デッドバンド = 摩擦とのリミットサイクル防止 (保持は内側 PI 積分器と
     ディザに任せる)。大ステップの到達時間を詰めたくなったら遠方のみ
     √プロファイル (一定減速度) に置換可。v_max 初期値はリリース試験の
     バネ戻り速度と同オーダーから。
   - **選定方法**: 同定モデル上で PID+FF と P/PI カスケード (推定器の
     ノイズ・遅れ込み) をシミュレーション比較してから実機に載せる。
     推定器のノイズ床は同定実験のログ (滞在中 = 真値 0 %/s) で事前検証できる。
   - **選定基準 (FF+PID vs カスケード)**: FF は「知識ベース」= 静的・再現性の
     ある外乱 (バネ曲線) に最強で、低リスク・低コスト・失敗が穏やか (マップが
     違っても I が補正)。カスケードは「計測ベース」= 変動外乱 (摩擦の経時変化・
     負圧トルク・Vbat/R 変動) を内側ループが常時吸収し、FF 路線で必要だった
     再測定/補正係数/FF_aero が構造的に不要になる — 性能の天井は高いが、
     速度推定の質に全てが懸かる (推定が汚いと内側ループが振動)。
     **分岐条件は「速度推定器のノイズ床で内側帯域 ~50–100 Hz が取れるか」**。
     折衷 (カスケード + バネ FF) も可能だが複雑さ最大。
   - 実験仕様は制御方式に依存しないため、この選択は同定完了後まで先送り可能。
8. **実走検証 (FF 導入後)**: 実走で `(θ, u, i, RPM)` をログし、定常保持中の
   `Kt·i − Ts(θ)` から負圧トルク (常に開き方向) 等の未モデル外乱の大きさを
   確認。Tc 比で無視できなければ `FF_aero(θ, RPM)` を追加 (§4 の注意参照)。
   これとは別に、**エンジン稼働中のスプリング閉じ復帰の実機確認** (§4 の
   安全上の含意) は FF 導入を待たず早期に行う。

## 8. 関連する既存コードへの注意

- target-vs-TPS プラウシビリティ (乖離 10% / 1 s でラッチ停止,
  `plausibility_validator.cpp`) はデフォルト有効。「行ききらない」量が 10% を
  超えてもシャットダウンしていないなら実機 flash config でこのチェックが
  無効化されている可能性がある → 要確認。FF 導入で追従が改善すれば本来の
  監視として再有効化できる。
- ETC 停止/再開は `main.cpp` の SHUTDOWN 安全層が一元管理。実験モード追加時も
  この層 (および MOTOR_OFF knob) を迂回しないこと。
- テレメトリは `SerialProtocol::sendDebugf` / proto 経由。素の `Serial.printf`
  禁止 (COBS フレーミング破壊)。
